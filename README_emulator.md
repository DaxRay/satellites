# Эмулятор призм: пошаговое движение, вращение и запуск main.py

Запуск:

```powershell
python "C:\Users\Lenovo\Desktop\mallocS\satelite\emulator.py"
```

Нужен обычный Python с tkinter. После сохранения правок в main.py нажми «Перезапустить main.py».

## Как исполняется main.py

В отдельном процессе выполняется весь сохранённый файл с `__name__ = '__main__'`. Исполняются и определения функций, и нижний блок `if __name__ == '__main__':`. Циклы управления берутся из твоего файла. Эмулятор не дописывает вызовы real_time или track: если они закомментированы, сопровождения не будет.

В памяти подставляются функции приборов: `A`, `move1`, `move2`, `stop1`, `stop2`. Файл main.py не переписывается. Исходное тело A можно включить настройкой `signal_from_main = True`; тогда показания могут быть случайными и не соответствовать нарисованному лучу. По умолчанию A моделирует физический прибор, а твой алгоритм получает только число.

Определять A в своём файле необязательно: прибор эмулятора доступен сразу. Если же включён signal_from_main, собственное определение A обязательно.

## Возврат к первоначальному main

По умолчанию `motor_mode = 'auto'`. Для первоначального кода с пустыми `move1()` / `move2()` и ручным `phig1 += move` / `phig2 += move` выбирается **step**:

- move1() и move2() поворачивают соответствующий диск на step_deg (1°).
- Вызов заканчивается после поворота. Время одного шага — step_seconds (0.02 с).
- Оба счётчика углов изменяет сам main; эмулятор второй раз шаг не прибавляет.
- A() измеряет сигнал после завершённого шага.

Для кода с ожиданием `while is_move2`, параметрами у функций движения или Timer внутри этих функций автоматически выбирается **continuous**. Его поведение описано ниже. Auto распознаёт эти распространённые формы кода, а не произвольный замысел программы. При неоднозначном варианте выбери step или continuous в настройках окна. Переписывать эмулятор не требуется.

Режим отображается над сценой и в отчёте. Лишние неиспользуемые переменные is_move1/is_move2 и импорт Timer сами по себе не включают непрерывное вращение.

## Непрерывное движение (continuous)

```python
move2(360)    # полный оборот за 1 секунду
move2(90)     # четверть оборота за 1 секунду
move2(-90)    # четверть оборота в обратную сторону за 1 секунду
```

Команда сразу возвращает управление. `is_move1` и `is_move2` равны True во время движения и False после его окончания. Новая команда тому же диску начинается из текущего промежуточного положения и заменяет предыдущую. Оба диска могут двигаться одновременно.

Длительность команды задаётся `turn_seconds` (по умолчанию 1.0). Здесь время фиксировано, поэтому скорость = заданный угол / turn_seconds. Это выбранная тобой модель привода, без разгона, люфта и пропуска шагов.

`move1()` без параметра означает угол `step_deg` (1°). `move2()` без параметра означает угол `default_turn2_deg` (360°). Можно менять оба значения в настройках.

В continuous второй угол phig2 обновляется непрерывно. В варианте main с phig1 += move счётчик первого угла остаётся под твоим управлением, а физический механизм первого диска моделируется отдельно. В step оба счётчика остаются под твоим управлением. Если хочешь автоматически обновлять оба угла, включи update_main_angles и убери свой ручной +=, иначе угол будет посчитан дважды.

Твой update_angles() может продолжать работать: адаптер устанавливает start_angle2, start_time2, speed2 и duration при команде. Истинное направление луча и A вычисляются из положения механизмов.

## Время и измерения

A считывает сигнал из текущего положения, пока диски вращаются. Измерение занимает measure_seconds (0.01 с). Вращение за это время продолжается. time.time(), time.monotonic(), time.perf_counter(), time.sleep() и Timer в main используют общие часы стенда.

Строке Python из main приписана малая стоимость python_line_seconds (0.00001 с), чтобы время проходило и в пустом while is_move2. Это условная стоимость, а не замер производительности компьютера. Импортируемые сторонние модули не исполняются построчно по этой модели. Не используйте стенд для оценки скорости Python на реальном контроллере.

Ползунок ускорения сокращает ожидание у экрана. Он не меняет ни длительность команды в секундах стенда, ни число запланированных измерений и пауз. При ускорении экран пропускает промежуточные кадры, A продолжает выполнять измерения.

## Спутник и этапы

При выполнении main() спутник заморожен относительно станции. После возврата из main() запускаются часы орбиты. Программа пользователя продолжает исполняться с той строки, которая стоит после вызова main(). Для сопровождения должен выполняться твой цикл real_time()/track(). Если файл закончился, эмулятор наблюдает оставшийся полёт без новых управляющих команд. Запущенные ранее повороты могут завершиться.

Ошибка в main отображается в отчёте вместе с частичными результатами поиска. Например, локальная переменная ans внутри main недоступна для print(ans) снаружи функции. Эмулятор сохраняет эту ошибку, не исправляя её за пользователя.

По умолчанию орбита круговая: 550 км над сферической Землёй, наклонение 53°, с учётом вращения Земли. Платформа на экваторе; начало — за 20 с до прохода над станцией. Это вымышленный пролёт для повторяемых испытаний, не данные настоящего спутника. При отрицательной высоте спутник скрывается за горизонтом.

## Что означают круги

Карта справа — вид неба со станции:

- Центр — прямо над головой, высота 90°.
- Внешний серый круг — горизонт, высота 0°.
- Серые внутренние круги — высоты 30° и 60°.
- Сверху север, справа восток, снизу юг, слева запад.
- Оранжевый пунктир — предел углов наведения. При одинаковых призмах спутник внутри него доступен для наведения. При разных призмах появляется ещё внутренняя недоступная область.
- Зелёная точка — спутник. Синий крест — направление луча.

Круг со стрелками в 3D-панели — отдельная схема сложения отклонений: синяя стрелка первой призмы, оранжевая второй, зелёная их сумма. Это не орбита спутника.

В приближённой модели равные призмы, направленные одинаково, дают максимальное отклонение. Направленные противоположно, компенсируют друг друга. Совместный поворот меняет азимут луча. Изменение взаимного угла меняет отклонение луча от вертикали.

## Оценка и точность

Отчёт разделяет найденные углы и фактическое положение антенны. Для поиска он сравнивает ответ с сеточным эталоном. Во время непрерывного вращения возможен ответ между узлами сетки, поэтому эталон служит ориентиром. Для сопровождения оцениваются доля времени связи, среднеквадратичная ошибка и длительность потери связи. Недоступные для наведения участки орбиты выделяются отдельно. Эталон и геометрия не передаются в main.

Модель призм — приближённая сумма эффективных углов отклонения, без точного преломления на поверхностях и без калибровки твоего изделия. Модель сигнала учитывает дальность, потери свободного пространства, ширину луча, частоту, усиления и измерительный шум. Это учебный стенд, не расчёт паспортных характеристик реальной антенны.

Настройки меняются в окне перед очередной проверкой. Постоянные значения задаются в sim_settings.py. Для записи JSON/TXT используй «Сохранить отчёт».
